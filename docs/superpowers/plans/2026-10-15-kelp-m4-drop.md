# Kelp M4 drag from Finder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drop files and folders from Finder onto the open folder, a folder row or a bucket, with a see-through drop panel and a pill saying where they will go.

**Architecture:** Three new Rust commands (`inspect_drop`, `plan_upload`, `start_uploads`) wrap the M3 helpers for any mix of paths. The UI listens to Tauri's webview drop events, picks the target with `elementFromPoint` + `data-drop` attributes, and runs one plan-then-ask flow that the Upload menu also uses.

**Tech Stack:** Rust, Tauri 2 (`getCurrentWebview().onDragDropEvent`), React 19 + TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-15-kelp-m4-drop-design.md`

## Global Constraints

- No comments in code; no `unwrap`/`expect` outside tests; `cargo fmt`, `clippy -D warnings`, `cargo test`, `npm test`, `npm run typecheck` pass at each commit.
- No new dependencies; no new Tauri capabilities; the UI never touches the filesystem.
- Semantic CSS tokens only; the panel's fade is 160 ms and off under `prefers-reduced-motion`.
- Copy (exact): pill `Upload {summary} to {destination}`; no target `Drop on a folder or a bucket`; summary `3 files · 412 MB`, `1 folder · 9.8 GB`, `1 folder and 2 files · 9.8 GB`, before the count `3 items`.
- Commits: plain messages, author ozan8@hotmail.co.uk, no `Co-Authored-By`.

## Review Focus

1. **Retina screens:** Tauri positions are physical pixels; a drop on a 2× display must pick the element under the pointer. Test `toCssPoint` in Task 2.
2. **No bucket open:** over the list with no place open there is no list target; only buckets accept. Test in Task 2.
3. **A dropped path removed before the drop:** `start_uploads` refuses with an `Io` error and queues nothing. Test in Task 1.
4. **The same item dropped twice in one drop** (Finder can send duplicates): it is uploaded once. Test in Task 1.
5. **Dropping onto a file row:** targets the open folder, not that file. Test in Task 2.
